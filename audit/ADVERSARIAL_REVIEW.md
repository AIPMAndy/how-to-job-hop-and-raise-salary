# 对抗式审核报告 · 普通人跳槽涨薪保姆级指南

**审核日期：2026-10-12｜审查对象：本次离线项目包，而非尚未上线的GitHub仓库。**

## 真实发现和已修复问题

1. **旧版章节偏短**：大多数只是5条简述；已增加20章专属“深入实操”，涵盖具体操作、反例、证据与失败路径。
2. **构建丢稿风险**：旧`build.py`会直接重写`guides/*.md`；新增`deepdives/`并由构建脚本追加。
3. **只给Markdown阅读不够方便**：现生成`read.html`和10份独立章节HTML，每页离线可读。
4. **跳槽README曾有重复表格分隔行**：重写为结构化README，链接经批量检查。
5. **网页默认填有演示薪酬**：修改为0元起始，避免误以为用户本人收入。
6. **过早承诺Pages地址**：现README默认指向仓库内的本地互动页；远程Pages必须上线后验收。
7. **模板少、真实边界不足**：扩展至25份，增加20 FAQ、5 AI Prompt、2个虚构完整演练。

### 特别说明：测试边界

浏览器环境禁止直接导航本地`file://`或`localhost`地址，因此本轮Chromium测试使用`set_content`加载本地生成的完整HTML，测量真实DOM交互与布局；**未等价测试真实GitHub Pages部署、iOS Safari双击本地文件、GitHub Pages HTTPS网络访问**。未做真实用户效果实验，也未连接实际人事系统或招聘系统。

## 复核流程（读者或贡献者）

1. 修改`data/tasks.json`的任务文字和`deepdives/`的深入内容，修改`SOURCES.md`的来源与口径。
2. 安装可选构建依赖`python3 -m pip install -r requirements-dev.txt`，再执行`python3 build.py`。
3. 运行`python3 -m unittest discover -s tests -v`；从首页点击任意章核对静态HTML。
4. 不收集真实工资流水与客户姓名；争议的政策观点提交Issue时附原文、时间、适用范围。

**审查结论**：静态内容、结构和Chromium组件级交互达到了本轮自测门槛。上线质量、真实用户操作体验与商业结果仍待实证验证。
